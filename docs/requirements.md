# 要件定義

作成日: 2026-09-25 / 状態: 初期仕様 / 管理者: moooyooo

本文の「必須」は目標仕様を示します。実装済み機能を示すものではありません。
工程番号は[開発工程](roadmap.md)に対応します。

## 1. 目的と用語

Windows Explorerに慣れた利用者が、Macでも同様の配置・操作でファイルを扱えるようにする。
用途ごとの複数フォルダと配置を保存し、作業環境を素早く切り替えられることを主な価値とする。

| 用語 | 定義 |
| --- | --- |
| プロセス／インスタンス | 独立したPIDで動くアプリ。複数同時起動を必須とする |
| MDI親ウィンドウ／ワークスペース | macOS上の通常のウィンドウ。1プロセスで複数開ける |
| Explorer／子画面 | 親ウィンドウ内で移動・サイズ変更できる独立したフォルダ閲覧画面 |
| プロジェクト | 1つの親ウィンドウ内のExplorer構成と配置を保存するファイル |
| セッション | 開いている親ウィンドウ、未保存状態など、そのインスタンスの復旧情報 |

**ユーザー確認済み:** 複数起動には、同一アプリ内の複数ウィンドウに加え、
アプリを別プロセスで複数起動することも含む。

## 2. 必須機能

### ウィンドウ・MDI

| ID | 要件 | 主工程 |
| --- | --- | --- |
| WIN-01 | 複数のMDI親ウィンドウを開き、それぞれ独立したプロジェクトを扱える | P1 |
| WIN-02 | 親の内部に複数の子画面を自由配置し、移動・サイズ変更・前後関係を操作できる | P1 |
| WIN-03 | 子画面の最大化／復元、最小化／復元、縦・横整列、重ねて表示、閉じるに対応する | P1 |
| WIN-04 | アクティブな親・子を明示し、メニューとショートカットを正しい対象へ送る | P1 |
| WIN-05 | 親のリサイズ・画面切り替え後も子画面のタイトルと操作部へ到達できる | P1 |
| INST-01 | メニューから別プロセスを起動でき、独立したPID・ウィンドウ・作業状態を持つ | P1 |
| INST-02 | 一方の終了・クラッシュが他方を終了させず、復旧情報も混線しない | P1/P3 |
| INST-03 | 同じプロジェクトの保存競合、共有設定・最近使った一覧の更新競合を処理する | P3 |

MDIは親の内部で子画面が重なる形式まで検証する。固定分割だけのUIへの変更は、
P1の実測・操作検証と理由を記録したうえで仕様として判断する。

### プロジェクト保存・切り替え

| ID | 要件 | 主工程 |
| --- | --- | --- |
| PRJ-01 | 新規、開く、保存、別名保存、最近使ったプロジェクトを提供する | P3 |
| PRJ-02 | 子画面ごとのフォルダ・配置・表示設定とアクティブな子画面を復元する | P3 |
| PRJ-03 | 通常の「開く」は別の親ウィンドウへ開く。「切り替え」は現在の親の構成を置き換える | P3 |
| PRJ-04 | 未保存変更がある場合の切り替え・閉じる・終了では、保存／破棄／キャンセルを選べる | P3 |
| PRJ-05 | 保存は原子的に行い、破損ファイル・未知のバージョン・保存失敗から既存ファイルを守る | P3 |
| PRJ-06 | 移動済みフォルダの再解決、未接続ボリュームの再接続、参照先の選び直しを可能にする | P3 |
| PRJ-07 | 同じファイルを別プロセスで開いた場合は最初の保持者だけ保存可能とする | P3 |
| PRJ-08 | インスタンス別に復旧情報を自動保存し、明示保存したプロジェクトと区別する | P3 |

保存する内容は、プロジェクト名・ID・形式バージョン、親の位置とサイズ、子画面の数・順序・
通常時の位置とサイズ・最大化／最小化、参照フォルダ、ツリー幅と展開状態、表示形式、
列構成、ソート、隠し項目設定、名前フィルター、アクティブ子画面とする。
選択中ファイル・スクロール・移動履歴はセッション情報として扱う。
コピー対象や実行途中のファイル操作はプロジェクトの再読込で再実行しない。

プロジェクトの読み取り専用表示は**構成ファイルの保存制限**を意味する。
表示中の実ファイルへの操作権限はmacOSの権限と各操作の判定に従う。
後から開いた側も配置を試せるが、保存には別名保存または編集権の再取得が必要になる。

### ファイル操作

| ID | 要件 | 主工程 |
| --- | --- | --- |
| FILE-01 | フォルダ作成、名前変更、コピー、切り取り・貼り付け、ゴミ箱への移動に対応する | P4 |
| FILE-02 | 子画面間・親間・アプリの別プロセス間・Finderとのコピーとドラッグ＆ドロップを提供する | P4 |
| FILE-03 | 同名衝突は置換・スキップ・別名を選べる。フォルダの自動マージは初期対象外 | P4 |
| FILE-04 | 処理中の項目・完了件数・失敗を表示し、キャンセルできる | P4 |
| FILE-05 | 同一／別ボリューム、権限不足、容量不足、切断、処理中の外部変更を扱う | P4 |
| FILE-06 | 安全に戻せる操作だけにUndoを提供し、対象操作と戻せない理由を明示する | P4 |

切り取り時点では実ファイルを移動しない。アプリの別プロセス間でも切り取り・貼り付けを
扱い、消費済みの移動要求を再実行しない。Finderとの切り取り意味の相互運用はP4で検証し、
確実に移動として解釈できない場合はコピーとして表示する。

削除の既定はゴミ箱。ゴミ箱に移せない場合に完全削除へ自動で切り替えない。
初期版で完全削除は提供しない。別ボリュームへの移動ではコピー成功を確認してから元を除去する。
キャンセルは初期版ではファイル単位の境界で完了する仕様とし、大きな単一ファイルの処理中は
「キャンセル待ち」を表示する。完了・失敗・未着手を分けて報告する。

Undoは名前変更・移動・ゴミ箱への移動と、作成した項目が変更されていない場合の新規作成・コピーを
初期候補とする。衝突や外部変更時には停止する。置換、アプリ再起動をまたぐUndo、別プロセスの
操作履歴のUndoは初期対象外。実行したプロセスの操作履歴に記録する。

## 3. UX・非機能要件

- **UX-01:** Explorerを基本にしたメニュー・配置・ショートカットを提供する。[詳細](ux.md)。
- **UX-02:** 日本語IME変換、テキスト編集中の削除・選択、OSの予約キーを妨げない。
- **UX-03:** キーボードだけで子画面の追加・切替・整列・保存と日常的なファイル操作を完了できる。
- **UX-04:** VoiceOver、明暗表示、拡大表示、状態を色だけに依存しない表現を検証する。
- **PERF-01:** UIはAppKit、処理はSwiftと標準フレームワークを中心にし、外部依存は必要性を記録する。
- **PERF-02:** 列挙・コピー・アイコン生成などの重い処理でUIスレッドを塞がない。
- **PERF-03:** ツリーは展開時に読む。一覧は行を再利用し、アイコン・監視・バックグラウンド処理に上限を設ける。
- **SAFE-01:** パスはURLとして扱い、ファイル名をシェルコマンドとして実行しない。
- **SAFE-02:** macOSの権限を尊重し、常時管理者実行や権限昇格用ヘルパーを前提にしない。
- **SAFE-03:** プロジェクトを開くだけでは外部プログラム起動・ファイル変更・任意コマンド実行を行わない。
- **PRIV-01:** 初期版はオフライン動作。利用状況の送信は行わず、ログに個人のパスを既定で残さない。
- **PUB-01:** 再現可能なビルド、意味のあるテスト、公開用資料と配布手順を段階的に整備する。

### 軽量化の暫定目標

以下は達成済みの値ではない。P1で測定条件と基準値を記録し、P5で判定する。
基準はApple Silicon・内蔵SSD/APFS・Releaseビルド・プレビューなしとする。
測定時には機種、メモリ、OS、ツールチェーン、データセットを記録する。

| 指標 | 暫定目標 | 測定条件 |
| --- | --- | --- |
| ウォーム起動 | 操作可能になるまで1秒以内（p95） | ローカル1,000項目、1親・1子、10回以上 |
| メモリ | physical footprint 150 MiB以下 | 1親・1子、1,000項目、安定後 |
| 複数画面のメモリ | 350 MiB以下／プロセス | 2親・合計6子、各1,000項目、安定後 |
| 待機時CPU | 1%未満／プロセス（1論理コア=100%） | 監視対象の変更なし、60秒平均 |
| 1,000項目の表示 | 300 ms以内（p95） | パス確定から初期ソート済み一覧を操作可能になるまで |
| 10,000項目の表示 | 1秒以内（p95） | 同上。10万項目は応答性と増分負荷を別途測る |
| アプリ容量 | 50 MiB以下 | Apple Silicon単体、配布用.app、デバッグシンボルを除く |

複数プロセスでは各プロセスと合計を記録する。ネットワークや外部ディスクは別系列で測り、
UI応答性とキャンセルの可否を評価する。未達時には測定結果・原因・変更案を残す。

## 4. 初期版の範囲と後続候補

P1〜P4で、複数プロセス・MDI・閲覧・プロジェクト復元・基本操作を持つMVPを作る。
P5〜P6で一般公開に向けた操作性、性能、互換性と配布品質を整える。

後続候補はアイコン表示、Quick Look、再帰検索、タブ、複数親をまとめたプロジェクト、
Intel向け配布、圧縮ファイル内の操作、Git状態表示、同期、拡張機能とする。
OSがマウント済みの共有ボリュームは閲覧対象とするが、独自のSMB/SFTPクライアントは初期対象外。
初期のプロジェクト書き込み先は、クラウド同期・ネットワーク共有の対象ではないローカルの
保存先とする。共有領域での複数端末共同編集は後続の検証対象とする。

## 5. 主要な受け入れシナリオ

| ID | シナリオと合格条件 |
| --- | --- |
| AT-01 | 親2つに子を3つずつ開き、自由配置・リサイズ・整列・最大化からの復元ができる |
| AT-02 | メニューから2つ目のプロセスを起動。異なるPIDを確認し、一方の終了後も他方で操作できる |
| AT-03 | A/Bプロジェクトを保存して再起動。フォルダ・配置・列・ソート・アクティブ子が復元される |
| AT-04 | 同じプロジェクトを2プロセスで同時に開く。保存権は1つだけで、他方は別名保存できる |
| AT-05 | 保存権保持プロセスを異常終了。残った側は再読込と排他再取得後に保存できる |
| AT-06 | 日本語入力中・パス編集中・一覧操作中で同じキーを使い、入力や別画面への誤操作がない |
| AT-07 | 1,000／10,000項目と6子画面で性能を測定し、待機中も不要な定期走査が続かない |
| AT-08 | コピー・移動・名前変更・ゴミ箱・Undoを一時データで検証。衝突・容量不足・キャンセルでも元データを失わない |
| AT-09 | 欠落フォルダ・未接続ボリューム・権限不足があっても他の子は開き、参照先を選び直せる |
| AT-10 | 未知の形式・不正な座標・重複ID・破損JSONを開いても既存プロジェクトを上書きしない |
| AT-11 | 子画面を閉じて開く操作を50回行い、監視・タスク・メモリが継続的に増えない |
| AT-12 | 別プロセス間でコピー／切り取り・貼り付けを行い、同じ移動要求の二重実行を防げる |
