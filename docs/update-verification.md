# 0.7.0 更新機能の検証

実施日: 2026-09-28。macOS 26.5、Apple M2 Max、64 GiB、Swift 6.3.2。
管理者・更新者はmoooyooo。一般配布用のDeveloper ID署名・公証は未実施。

## 実装とローカル試験

- Sparkle 2.10.0をタグのコミットとバイナリのチェックサムで固定。
- 248翻訳キーの日英一致を確認。
- 統合試験は97定義中91件を実行して成功（8.103秒）。
  任意実行のボリューム3件・性能3件は通常実行では除外し、別途実行して成功。
  別APFSボリューム・実容量不足の3件は0.436秒、性能3件は139.038秒。
  配布スクリプトのPython試験6件、シェル構文、署名・リソースの検証も成功。
- 更新専用のSwiftテスト11件が成功。生存する別プロセス、同時ロック昇格、
  エイリアス、別アプリコピー、異常終了、更新障壁、1回だけの復元、
  OS起動ID変更による復旧、破損データとダウングレード拒否を確認。
- AppKitで操作シート中の終了拒否、未保存構成の復元、外部で変更された
  プロジェクトを上書きしないこと、隔離インスタンスでの更新無効化を確認。
- 復元時の比較を保存ファイルのSHA-256にした。bookmarkの解決による
  `/var`と`/private/var`の表記差を、外部編集と誤判定しない。
- 非アクティブ時の終了確認が、既に開いている操作シートのある親を使用するよう修正。
- 実プロセス試験では、無操作で開いたプロジェクトが未変更のままであることも確認する。
  明示的な`--diagnostics-file`指定時だけ、終了要求を受けた時点の処理中・未保存・
  シート表示の件数を別ファイルへ記録する。通常起動では記録せず、ファイル名やパスも出力しない。

## 実際のSparkle更新

`python3 scripts/test-updates.py`で固有Bundle IDの使い捨てアプリと鍵を生成した。
プロダクションのキーチェーンの鍵、起動中の利用者アプリ、個人ファイルは使用しない。

| シナリオ | 結果 |
| --- | --- |
| 署名付き1→2のZIP更新 | 入れ替え・再起動後にbuild 2を確認し、画面スナップショットを復元 |
| 最初の終了要求を拒否 | 旧プロセスを保持し、再試行後にのみ更新 |
| 署名後にフィードを書き換える | 拒否。build 1を維持 |
| 正しいフィードで、署名後のZIPを書き換える | 署名エラー4005で拒否。build 1を維持 |
| 配布用の空フィード | キーチェーンに触れず公開鍵のみで署名検証成功 |

更新ツール・テスト用HTTP例外・テスト鍵は配布アプリに含めない。
通常のアプリと同梱Sparkle・XPC・Updater・Autoupdateの署名を検証した。
公開フィードに実リリースを登録するための署名・公証済みZIPはまだない。
