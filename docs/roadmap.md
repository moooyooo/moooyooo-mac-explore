## 2. P1で最初に行う作業

1. Swift Packageを作り、Core・Platform・Appの依存関係とビルド方法を固定する。
2. `.app`生成スクリプト、Info.plist、アプリ識別子、起動手順を追加する。
3. 親2つ・各子3つのMDIを作り、移動・リサイズ・最大化・最小化・整列を確認する。
4. 共通のコマンド経路を作り、メニュー・キー操作・アクティブ子の関係を確認する。
5. 別プロセス起動とプロジェクト引き渡しの入口を作り、PID・終了・再起動の独立性を確認する。
6. macOS 14を下限としたAPIの可用性、権限方針、UI自動テストに必要な環境を記録する。
7. Releaseビルドの起動・メモリ・CPUを測り、MDIの見通しと残課題を記録する。
8. 意味のある最初のテストとビルドをmacOS CIで実行できるようにする。

実装内容とローカルの確認結果は[P1の実装記録](p1-verification.md)へ記録する。
プロジェクト形式の引き渡しはP3の読み込み処理と合わせて追加する。
P1では`--folder`引数の複数受け渡しと別プロセスへの起動引数を実装している。

この工程ではファイル内容を書き換えない閲覧用の試作を用いる。
MDIが性能または操作性を満たせない場合は、原因と代替案を記録して要件への影響を判断する。

容量不足など通常環境で安全に再現しにくい事象には、失敗を注入できるファイルアクセス層と
専用のテストボリュームを使う。日常利用データで破壊的な試験を行わない。
UI確認の記録には実施したOS・機種・手順・結果を残し、未実施を明示する。

性能は[要件の測定条件](requirements.md)を使い、実装前後で比較する。
複数プロセスの合計負荷、閉じた画面のタスクと監視の解放も対象に含む。

## 4. Git・CI・変更の運用

- 既定ブランチは`main`。実装は機能や不具合ごとの短いブランチを基本にする。
- 管理者のローカルGit名義は`moooyooo`。公開用noreplyメールをリポジトリ単位で設定する。
- ビルド生成物、署名情報、個人のパスを含むプロジェクトや復旧情報は追跡しない。
- 動作変更と対応する資料・検証をひとまとまりにしてコミットする。
- GitHub接続後はPRでビルド・テストを実行する。macOSとSwiftの検証バージョンを明示する。
- GitHub Actionsは最小権限で構成し、外部PRの検証に署名用の秘密情報を渡さない。
- Swift TestingのテストとmacOS用CI定義を追加済み。GitHubへpush後にCIの実行結果を確認する。

初期コミットには、README、要件、UX、設計、工程、開発規約とリポジトリ設定ファイルを含める。
GitHub上のリポジトリ作成・pushはソース公開の準備が整う工程で実施する。

## 5. 公開条件

### ソースをGitHubへ公開する条件

- [x] ライセンスを決定し`LICENSE`へ記載する（MIT）。
- [x] READMEに英語の概要、対応環境、実際に動くビルド・起動手順を記載する。
- [x] 現在の機能・制限、ロードマップ、変更履歴、貢献方法を掲載する。
- [x] 日常利用のパスや私的データを含まないスクリーンショット・合成サンプルを用意する。
- [ ] 必要なテストとmacOS CIが通り、別の環境でもビルドを再現できる。
- [x] アセット・依存関係の出所とライセンスを整理する。
- [ ] 不具合・機能要望のテンプレートとセキュリティ報告先を整備する。
- [ ] `moooyooo`名義の公開先とリポジトリ名を確定する。

### 一般利用向けバイナリを配布する追加条件

- [ ] 最小対応OSと現行OSで主な受け入れシナリオを確認する。
- [ ] データ消失につながる既知の不具合が残っていない。
- [ ] 性能の計測結果と対応するハードウェアを記載する。
- [ ] Developer ID署名、Hardened Runtime、公証とチケット付与を完了する。
- [ ] 新規環境でダウンロードから起動まで確認する。
- [ ] バージョン、リリースノート、チェックサム、形式移行時の扱いを記載する。

ソース公開を先行する場合は、開発段階と未検証事項をREADMEに表示する。
公開バイナリの署名・公証に必要な環境はP6で確認し、ローカル開発の開始とは切り離す。

## 6. 先に検証する不確実性

| 課題 | 影響 | 対応工程と判断材料 |
| --- | --- | --- |
| 独自MDIのフォーカス・アクセシビリティ | 操作の誤送信、使いにくさ | P1で重なり・キー操作・VoiceOverを早期確認 |
| 別プロセス間の状態共有 | プロジェクトや復旧情報の上書き | P3で実際の2プロセスによる競合・異常終了試験 |
| 大量ファイル・多数画面 | メモリ増加、UI停止 | P2で計測、P5でキャッシュ・監視・並列度を調整 |
| ファイル操作の中途失敗 | データ保全と再実行の問題 | P4で段階ごとの失敗注入と結果検証 |
| macOS権限と配布設定 | 閲覧不能、他環境で起動できない | P1で方針検証、P5/P6で権限・署名・初回起動を確認 |
