# 0.7.2 development preview

Maintainer: **moooyooo**. No notarized public binary has been released.

## Fix

The startup disk entry under Volumes was visible but could not be opened or expanded.
On the development Mac, `/Volumes/Macintosh HD` is a symbolic link to `/`.
Foundation's URL directory enumeration rejected the link with Cocoa error 256,
underlying POSIX error 20 (`ENOTDIR`); enumerating `/` succeeded.
This was an application bug, unrelated to the system volume's write protection.

`DirectoryReader` now resolves the directory for enumeration in its background task.
Returned entries retain the entered path so addresses, navigation history and child
file actions continue to use the selected link. Permission failures and invalid
targets still produce errors. File mutation and symbolic-link copying rules are unchanged.

## Verification

- Before the fix, the new regression failed for absolute, relative and chained links
  with the same error as the real startup-disk entry.
- After the fix, all three variants passed, including hidden files, Unicode names,
  nested folder links and preservation of child entry paths.
- Broken links, cycles and links to regular files are rejected.
- The AppKit regression passed tree expansion, navigation into a linked volume and
  its child folder, and Back navigation while retaining the link path.
- Local integration: 105 test definitions, 99 active tests passed in 10.745 seconds;
  6 optional volume/performance tests were skipped. All 248 translation keys and
  Release bundle metadata/resources/nested signatures passed verification.
- The real `/Volumes/Macintosh HD` was opened by the 0.7.2 Release app in an isolated
  process: its startup report confirmed one ready pane with four visible entries,
  matching the root listing. The check only read the real disk; mutation tests used
  synthetic folders. This was an app-state check, not Computer Use visual inspection.

The 0.7.1 sidebar-shaking fix remains in place; the user confirmed its resolution.
I-06 (unexpected dirty state in a read-only project's macOS 26 CI termination test)
and the existing manual/general-distribution gates remain open.
Project schema version 1 and the empty signed update feed are unchanged.
