# 自動アップデート

更新: 2026-09-28 / 0.7.0開発版。更新者・公開先・Git名義は **moooyooo**。

## 現在の状態

Sparkle 2.10.0を固定して組み込み、署名付きの更新一覧・ZIPの検証、
実際の入れ替え・再起動・復元を使い捨てのテストアプリで確認した。
配布用Ed25519鍵はログインキーチェーンのアカウント
`moooyooo/moooyooo-mac-explore`に保存している。Gitに入れるのは公開鍵だけ。

**署名・公証済みの一般向けバイナリは未公開。** 現在の署名付きフィードは空。
管理者からApple Developer Program未登録との回答があり、
Developer ID署名・公証・別Macでの実配布更新は登録後に検証する。
0.6以前にはアップデータがないため、最初の対応版は手動でインストールする。

## 利用者の操作

アプリメニューに次の項目を追加した。英語／日本語に対応する。

| 項目 | 動作 |
| --- | --- |
| アップデートを確認 | その場で更新を確認 |
| アップデートを自動確認 | 有効な場合、起動中に1日1回確認。初期値オフ |
| 更新を自動ダウンロードして終了時にインストール | 有効な場合、確認した更新をダウンロードし通常終了時に適用。初期値オフ |
| ダウンロード済みの更新をインストールして再起動 | 準備済みの更新を適用。作業中は待機 |

アプリが動作していない間に確認する常駐サービスは追加しない。
自動確認は起動30秒後から、15分ごとに必要性を判定する。
別プロセスやファイル操作で延期した場合、後の確認機会に再試行できる。
手動確認は自動確認設定がオフでも利用できる。
`--support-directory`を指定した隔離テスト用インスタンスでは更新しない。

### 作業と複数起動

- 同じ場所にあるアプリを複数起動している間は更新確認を延期する。
  他のプロセスを自動終了しない。別の場所のアプリコピーとは排他を分ける。
- 確認・ダウンロード・インストール待ちの間は、新しいプロセスの起動を抑止する。
  更新がない場合、取消、署名拒否などでは排他を解放する。
- ファイル操作、プロジェクトのダイアログ、プロジェクトを開く処理中には終了しない。
  操作を終えてから更新画面またはアプリメニューで再試行する。
- 再起動前に、全MDI・子画面・未保存の構成・選択・表示位置・履歴を
  個人用の更新チェックポイントへ原子的に保存する。保存失敗ならアプリを終了しない。
- 更新後は、変更されていないプロジェクトに編集権を取得して接続し直す。
  外部で変更された／消えたプロジェクトは未保存コピーとして復元する。
  元の`.mexplore`を自動上書きしない。Undo履歴は再起動をまたがない。

### 更新中に異常終了した場合

確認開始時にも画面構成と更新障壁を保存し、プロセス終了から
Sparkleの入れ替え完了までの隙間に古い実行ファイルが起動しないようにする。
更新後の版が復元情報を新しいセッションへ保存してからチェックポイントを消す。

更新が中断して旧版の起動が止まった場合は、**Macを再起動するか、
更新先の新しい版を同じ場所へ手動インストール**する。
OSの起動セッションが変われば以前のインストーラは残らないため、
旧版でも保存した画面を復元できる。時間経過だけでは更新障壁を解除しない。
チェックポイントを手作業で削除して回避すると復元情報を失う可能性がある。
確認開始後に追加した変更は、通常の「セッションを復旧」にも残り得る。

排他は同一macOSユーザー内の協調プロセスが対象。
他のログインユーザーが同じアプリを使用中の更新は未検証で、一般配布前の確認対象。

## 配信と署名

`Resources/Info.plist`の`SUFeedURL`はこのリポジトリの`main/updates/appcast.xml`。
更新ZIPは`moooyooo/moooyooo-mac-explore`のGitHub Releasesに置く。

- HTTPS、署名付きフィード必須、アーカイブの展開前署名検証を有効化。
- アプリ側でもフィード署名の成功、単調増加する整数ビルド番号、
  moooyoooのリポジトリ内の更新ZIP URLを検証。
- プロファイル送信は無効。GitHubには通常のHTTP通信情報が届く。
  プロジェクト、個人パス、ファイル内容は送らない。
- 鍵のバックアップは管理者が安全な保管先で行う。チャット・Git・CIログへ秘密鍵を出さない。
  配信鍵の紛失・漏えい時は、Sparkleの鍵移行手順を確認してから対応する。
- Sparkle.frameworkとインストーラを内側から署名し、外側のアプリを最後に署名する。
  署名には`--deep`を使わず、検証にのみ使用する。

公式資料: [プログラムからの組み込み](https://sparkle-project.org/documentation/programmatic-setup/)、
[公開手順](https://sparkle-project.org/documentation/publishing/)、
[セキュリティ](https://sparkle-project.org/documentation/security-and-reliability/)。

## moooyoooによる今後の更新

1. バージョンと整数`CFBundleVersion`を増やし、リリースノートを更新する。
2. ソース、翻訳、データ保全、更新のテストを通し、moooyooo名義でコミットする。
3. [配布手順](releasing.md)に従いDeveloper ID署名・公証済みZIPを作る。
4. 以下で鍵・署名・公証・公開先・ビルド番号を確認し、署名付きフィードを準備する。

```sh
python3 scripts/prepare-update.py dist/Moooyooo-Mac-Explore-0.7.0-arm64.zip
```

これは`dist/update-v0.7.0/`を作るだけで、公開は行わない。
開発版ZIP、未署名・未公証、汚れた作業ツリー、違う鍵・リポジトリ・ビルド番号は拒否する。
公式ツールは`scripts/fetch-sparkle-tools.sh`でSHA-256検証後に取得する。

5. GitHubの`moooyooo`として`v0.7.0`のReleaseを作り、対応するZIP・チェックサム・
   ビルド記録・ノートをアップロードする。対象コミットとアーキテクチャを確認する。
6. Releaseを公開して、**匿名ダウンロードしたZIPのSHA-256と署名を確認する**。
7. その後にだけ生成した`appcast.xml`を`updates/appcast.xml`へコピーし、
   moooyooo名義でコミット・pushする。署名後のXMLは編集しない。
8. インストール済みの旧版から確認・更新・終了延期・復元を新規環境で試す。

初期対応はApple Silicon。アプリを複数アーキテクチャへ展開する際は、
生成される`sparkle:hardwareRequirements`と各配布物を実機確認する。
現在のスクリプトは単一のホストアーキテクチャを扱い、未検証のIntel版を混在させない。
ダウングレードは配信せず、不具合修正はより大きいビルド番号で配信する。
CIや外部PRに配布用秘密鍵は渡さない。

## 再現できる検証

```sh
scripts/build-app.sh release
scripts/test.sh --integration
python3 scripts/test-updates.py
python3 scripts/verify-app.py
```

更新試験は一時ディレクトリ、使い捨てEd25519鍵、固有Bundle ID、
ループバックHTTPを使う専用`UpdateProbe.app`で実行する。
本体にはHTTP例外、テスト鍵、テスト用実行ファイルを同梱しない。
署名付きの1→2更新、終了拒否後の再試行、復元、フィード改ざんとZIP改ざんの拒否を確認する。
別プロセス排他、OS再起動後の復旧判定、外部変更の保全はSwiftテストでも確認する。
実際のMac再起動・公証版の更新・別MacのGatekeeper・標準更新画面の手動受け入れは未実施。
更新検証のローカル結果は`.local/update-verification.json`へ保存する。
実施結果と容量・起動・メモリの測定は[検証記録](update-verification.md)にまとめた。
