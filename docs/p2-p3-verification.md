# P2/P3 実装・検証記録

実施日: 2026-09-25 / バージョン: 0.2.0

## 環境とビルド

- macOS 26.5（25F71）、Apple M2 Max、64 GiB、ローカルAPFS。
- Swift 6.3.2、Command Line Tools。対応下限の宣言はmacOS 14。
- 実行時の外部依存なし。AppKit、Foundation、CoreServices、CryptoKit、Darwinを使用。
- `scripts/build-app.sh release`成功。Info.plist検証、ad-hoc署名検証に成功。`.app`は約1.2 MiB。
- `scripts/test.sh --integration`成功。**32テスト・1 suite、7.608秒**。
  変更監視のテストは通常ディレクトリ／OSの一時ディレクトリの2ケースを含む。
- GitHub Actionsは未実行。最小対応OS、Intel、外部・ネットワークボリュームは未検証。

## 実装した内容

- 展開時に読むフォルダツリー、パンくず、ツリー幅、お気に入り、名前による一覧の選択。
- 列挙・フィルター・ソートを独立Taskで処理し、古い結果を破棄。
- 同じフォルダのFSEvents監視を共有し、終了・取消で解放。前面復帰・マウント・F5でも再読込。
- プロジェクトの保存・別名保存・別の親で開く・現在の親で切り替え・最近使った一覧。
- フォルダ、子の順序と重なり、通常枠、最大化／最小化、アクティブ子、列幅と順序、
  ソート、フィルター、隠し項目、ツリーの設定を保存・復元。
- 親を閉じる・終了・切り替え時の未保存確認。失敗後の未保存状態の維持。
- 形式検証、サイズ制限、bookmarkによるフォルダの再解決。
- 専用inodeのOSロック、後発プロセスの読み取り専用、再取得、外部変更時の上書き停止。
- 同一ディレクトリでの一時書込み・flush・原子的置換。
- インスタンス別の構成の復旧、使用中セッションの除外、排他的な復旧の引き継ぎ。
- `.mexplore`のUTTypeとファイルを開くイベント、`--project`、保存済み構成の別プロセス起動。

## 検証した対象と結果

| 対象 | 結果 |
| --- | --- |
| JSON往復、設定・最大化・最小化・追加順・重なり順 | 一致 |
| 未知バージョン、破損JSON、サイズ超過、重複ID、NaN／無限、範囲外座標、非file URL | 拒否 |
| 複数の保持者、別名保存、保存後のrevision更新 | 保存権は1つ、コピーには新しいID |
| 元ファイルの外部変更・削除、破損後の再取得 | 上書きせず失敗を返す |
| ステージング途中の容量不足（ENOSPCを注入） | 元データ維持、一時ファイルを除去 |
| ステージング中の外部書換えを注入 | 置換直前に検出、外部データ維持 |
| シンボリックリンクによる別表記、ハードリンク、書込み不可 | 別表記は同じロック、後二者は読み取り専用 |
| 実際の別プロセスで同時オープンと保存試行 | 後発の保存を拒否 |
| 保持プロセスをSIGKILL、その後に再オープン・保存 | OSロックを再取得して保存成功 |
| フォルダを保存後に改名 | bookmarkで新しい場所へ解決 |
| 生存中／終了後のセッション、同時復旧、破損セッション | 生存中は除外、復旧の二重消費を拒否、破損は保全 |
| 最近使った一覧へ並行して20件の更新 | 全件を保持し、重複せずマージ |
| 同じフォルダに2つの監視、ファイル作成・内容変更 | 1ストリームを共有し両者へ通知 |
| 監視を50回開始／取消 | 終了後のストリーム数0 |
| AppKitコントローラに構成を復元、整列・保存・子を閉じる | 列設定と状態が一致、変更を未保存として追跡 |
| 画面外の親位置からのAppKit復元、不正データの復元 | 利用できる画面内へ補正、不正復元では既存構成を維持 |
| `.app`を2つ起動して同じプロジェクトを復元 | 別PID、2子を復元、後発は読み取り専用 |
| `.app`の正常終了後 | 各自の復旧ファイルを削除、保存権を解放 |

ファイル書込み・改名・権限変更・強制終了の試験は、テストが作成した一時データと専用子プロセスだけを対象にした。
テスト用アプリのApplication Supportも一時ディレクトリへ隔離した。

### 検証中に直した不具合

FSEventsが`/private/var/...`を返す一方、FoundationのURL正規化が`/var/...`を返すケースで、
登録済みパスとの照合に失敗した。POSIX `realpath`による正規化へ変更し、両方の場所で
作成・内容変更を検出する回帰試験を追加した。診断用のパス出力は製品コードに残していない。

## 性能の参考値

今回のRelease版と合成データで測定した。P5の全条件を満たす性能認定ではない。

| 対象 | 結果 | 測定範囲 |
| --- | --- | --- |
| 10,000項目、10回 | p95 **156.54 ms** | DirectoryReader＋初期フィルター・ソート。画面描画を含まない |
| 親2つ・合計6子、各1,000項目 | **約86.3 MiB** | 最初の一覧完了から3秒後のphysical footprint、1回 |
| 同じ6子の起動 | **0.654秒** | main開始→最初の子の一覧完了、1回。全画面の操作可能時間ではない |
| 同じ6子の待機CPU | **0.0%** | 変更なし60.016秒、`ps`のCPU時間差。分解能未満の使用は含み得る |

処理ベンチマークは`swift run -c release BrowserBenchmark .local/fixtures/10000 10`で再現できる。
ローカルの生データは`.local/p2-browsing-10000.json`、`.local/p2-metrics-multi.json`、
`.local/p2-idle-multi.json`に保存し、Gitでは追跡しない。

## 未実施・残る制約

- Computer Useのアプリ一覧取得は成功したが、ネイティブ操作の接続は許可完了後も
  ツール側で「権限待ち」と返った。マウス操作・ダイアログの保存／破棄／取消・IME・VoiceOverを
  実操作で確認できていない。AppKitのプログラムによる検証と目視・実操作の検証は別に扱う。
- 最小対応OS、JIS/US配列、明暗表示、DPI・複数モニターの実機切替は未検証。
- 一覧を操作できるまでのp95、100,000項目、実画面50回開閉のメモリ推移はP5で測定する。
- 復旧対象は構成・表示設定。選択、スクロール、移動履歴は未復旧。
- リモート保存先は拒否する。クラウド同期やロックを無視する外部アプリとの競合は保証しない。
- 一般ファイルのコピー・移動・改名・ゴミ箱・DnD・Undoは未実装。

手動確認時は、合成データでA/Bプロジェクトを作り、保存・別名保存・再オープン・切り替え・
終了時の3つの選択肢を確認する。次に同じプロジェクトを別プロセスから開き、読み取り専用の
表示と別名保存、先行側終了後の再取得を確認する。失敗時には元ファイルの内容を比較する。
